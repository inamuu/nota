# nota

[Acta](https://github.com/inamuu/Acta)（デスクトップのメモアプリ）のデータを、
ターミナルから読み書きするための TUI。

操作はすべてキーボードで完結する。マウスは使わない。

```
┌ Menu ──────────────────────────────────────────────────────────┐
│  1 ノート    2 ToDo   3 プロジェクト    4 検索                  │
└────────────────────────────────────────────────────────────────┘
┌ 日付 30/348 ───┐┌ 2026-08-26 ───────────────────────────────────┐
│▌ 2026-08-26  2 ││── 2026-08-26  ToDo ───────────────────────────│
│  2026-08-25  2 ││# ToDo: 2026/08/26（水）
│  2026-08-24  1 ││- 新OpのOpenSearchバージョンアップ
│  2026-08-21  3 ││  - [-] ローカル検証
```

## 4 つのビュー

`1` `2` `3` `4` か `Tab` で切り替える。

| ビュー | 内容 |
| --- | --- |
| ノート | デイリーノートを日付の新しい順に一覧し、選んだ日のエントリを表示 |
| ToDo | 全ノートから ToDo のタスク行を集めて一覧 |
| プロジェクト | プロジェクトと、そのタスクを状態別に表示 |
| 検索 | 全エントリを対象にインクリメンタル検索 |

件数が多いところは既定で絞ってある。ノート一覧は直近 30 件（`a` で全件）、
プロジェクトはアーカイブ済みを隠し（`A` で表示）、完了タスクは 5 件まで。
数はいずれも設定で変えられる。

## 編集

編集はすべて `$EDITOR` で行う。`$VISUAL` か `$EDITOR` を見る
（`nvim -u NONE` のような引数付きの指定も通る）。エディタを閉じると元の画面に戻る。

| キー | 何を開くか |
| --- | --- |
| `e` | 選択中のエントリ。プロジェクトビューではタスク一覧 |
| `o` | 新しいエントリ。プロジェクトビューでは新しいプロジェクト |
| `t` | 今日の ToDo |

エディタに渡すのは**編集してよい部分だけ**で、ファイル全体は開かない。
`<!-- acta:comment -->` のメタ行や閉じマーカーに人が触れる余地をなくすためで、
開いた瞬間に編集対象だけが出るので目的の箇所を探す必要もない。

### エントリ

```
tags: ToDo, Terraform

# ToDo: 2026/08/26（水）
- プロジェクト
  - [ ] タスク
```

1 行目がタグで、空行のあとが本文。タグはカンマ区切り。1 行目を消して保存すると
タグなしになる。

`o` で作ったエントリは、その日のノートに追記される。ファイルが無ければ
`posts/YYYY/MM/DD/` ごと作る。Acta のデータは「1 日 1 ファイル、中に複数エントリ」
なので、新しいノートを書く操作は既存ファイルへの追記になる。GUI と同じ挙動。

### 今日の ToDo

`t` で今日の ToDo を開く。まだ無ければ、アーカイブしていないプロジェクトの
進行中タスクを並べた雛形を出す。

```
tags: ToDo

# ToDo: 2026/08/26（水）
- プロジェクト A
  - [-] 進行中の作業
- プロジェクト B
  - [-] 別の作業
```

そのまま保存すれば今日のノートに入り、ToDo ビューに出る。手で行を足しても、
消してもよい。すでに今日の ToDo があるときは、新しく作らずそれを開く。

### ToDo の見え方

既定は日付の新しい順で、完了したものも含めて全部出る。`f` で未完だけになり、
`s` で並び順が日付 → 状態 → プロジェクト → 日付…と変わる。どちらも見出しに出るので、
今どの見え方かは常に分かる。並びや絞り込みを変えても、選んでいた行は追いかける。

チェックを進めるだけなら `Space` でよい（未着手 → 進行中 → 完了）。

### プロジェクト

`o` で新しいプロジェクトを作る。エディタに名前を 1 行書いて保存すると、
`projects/<名前>/` に `project.json` と空の `knowledge.md` を置く。ディレクトリ名は
Acta と同じ規則で名前から作り、英数字が残らない名前（日本語だけなど）は
`project-<日時>` になる。

一覧の並びは `J` / `K` で入れ替えられる。既定は更新の新しい順だが、触るたびに
入れ替わって探しにくいときに使う。並びはデータディレクトリの
`.nota/project-order.json` に持つ。`project.json` に書くと、Acta がそのプロジェクトを
保存したときに落ちてしまうため。

### プロジェクトのタスク

プロジェクトビューで `e` を押すと、タスク一覧をチェックリストとして開く。
行の追加・削除・並べ替え・状態の変更をまとめて行える。

```
- [-] 進行中のタスク
- [ ] 未着手のタスク
- [x] 完了したタスク
```

`[-]` が進行中、`[ ]` が未着手、`[x]` が完了。記法を覚えていなくても、名前だけを
並べて保存すれば未着手のタスクになる。空行と `#` で始まる行は読み飛ばす。
1 行も読み取れなかったときは、その旨を出して何もしない。

保存すると `project.json` に反映する。タイトルが一致する既存タスクは `id` や
`createdAtMs` を引き継ぐので、名前を変えた行は別のタスクとして扱われる。
nota が読まない項目（`sourceType` など）も残す。

状態だけ変えたいときは `Space` でよい。カーソルは並び替わったあとも同じタスクを追う。

### プロジェクトから今日の ToDo へ

タスクを保存すると、今日の ToDo にも反映する。進行中のタスクはプロジェクト名の
グループに足され、すでに同じ行があればチェック欄だけ更新する。ToDo 側で手を入れた
行は消さない。今日の ToDo がまだ無いときは何もしないので、先に `t` で作っておく。

## データの扱い

Acta とは同じファイルを読み書きする。読み込んだ内容は原文の行をそのまま保持し、
パース結果は行番号でそこを指す。書き戻しは該当行を差し替えて再結合するだけなので、
空行・記法の揺れ・nota が解釈しない行はそのまま残る。全ノートで原文を復元できるか
確かめるテストがあり、データ形式に手を入れたときはこれを通す。

危ない操作には歯止めを入れてある。本文やタスクを空にして閉じても消さず、削除は `D` で
確認を挟む。保存に失敗したときは画面の状態も元に戻して、ファイルと表示が食い違わない
ようにする。

外から変わったとき（Acta で編集した、git で入れ替えたなど）は `r` で読み直す。
nota 自身の編集のあとは自動で読み直すので、押す必要はない。

## インストール

Rust ツールチェーンは [mise](https://mise.jdx.dev/) で管理している。

```sh
mise install
mise run build          # リリースビルドして /usr/local/bin に配置
```

`mise run build` はリリースビルドしたバイナリを `/usr/local/bin/nota` に上書きする。
`/usr/local/bin` が root 所有なら sudo に切り替わるので、パスワードを聞かれる。

配置せずビルドだけしたいときは `mise run release`（`target/release/nota` に出る）、
コンパイルが通るかだけ見たいときは `mise run check`。

## 設定

Acta のデータディレクトリを教える必要がある。パスはローカル固有の情報なので、
リポジトリには含めない。

推奨は `~/.config/nota/config.toml` に置く方法。

```toml
data_dir = "/path/to/your/Acta"

# ノート一覧に最初から出す件数。既定は 30。0 なら最初から全件。
recent_notes = 30

# プロジェクトの完了タスクを出す件数。既定は 5。0 なら全件。
project_done_limit = 5
```

リポジトリ内に置きたい場合は `config.local.toml`（gitignore 済み）を使う。

```sh
cp config.example.toml config.local.toml
```

探索順は次のとおりで、最初に見つかったものを使う。`posts/` か `projects/` を
含むディレクトリでなければ次の候補へ進む。

1. `--data-dir <PATH>`
2. 環境変数 `NOTA_DATA_DIR`
3. 環境変数 `NOTA_CONFIG` が指すファイルの `data_dir`
4. `./config.local.toml` の `data_dir`
5. `~/.config/nota/config.toml` の `data_dir`
6. `~/Documents/Acta`

`--data-dir` と `NOTA_DATA_DIR` は明示指定として扱い、そこにデータが無ければ
別の場所へフォールバックせずエラーにする。どこから読まれたかは `?` のヘルプ画面に出る。

## 起動

```sh
mise run run                        # cargo run
nota                                # 設定ファイルから解決
nota --data-dir /path/to/Acta       # 直接指定
```

起動時にロゴと読み込んだ件数が出る。キーを押すか、少し待つと消える。

## キー操作

`?` でいつでも一覧を表示できる。低い端末で入りきらないときは `j` / `k` で送れる。

| キー | 動作 |
| --- | --- |
| `j` / `k`, `↓` / `↑` | 選択を上下に移動 |
| `Ctrl-d` / `Ctrl-u` | 半画面ずつ移動 |
| `g` / `G` | 先頭 / 末尾へ |
| `1` / `2` / `3` / `4` | ノート / ToDo / プロジェクト / 検索 |
| `Tab` / `Shift-Tab` | Menu を順に切り替え（検索の入力中も効く） |
| `h` / `l` | 一覧と本文のフォーカスを移動 |
| `Enter` | ノートは本文へ、検索は該当箇所へジャンプ |
| `Space` | ToDo / タスクの状態を進める（未着手 → 進行中 → 完了） |
| `t` | 今日の ToDo を開く / 進行中のタスクから作る |
| `o` | エントリ / プロジェクトを新しく作る（`$EDITOR`） |
| `e` | エントリ / タスク一覧を編集する（`$EDITOR`） |
| `D` | エントリを削除する（確認あり） |
| `/` | 全文検索。`Esc` で元のビューに戻る |
| `a` | ノート一覧を直近だけ / 全件で切り替え |
| `A` | アーカイブ済みプロジェクトの表示を切り替え |
| `s` | ToDo の並び順を変える（日付 / 状態 / プロジェクト） |
| `f` | ToDo を未完だけにするか切り替え |
| `J` / `K` | プロジェクトの並びを下 / 上へ入れ替え |
| `r` | データを再読み込み |
| `?` | このヘルプ |
| `q`, `Ctrl-c` | 終了 |
| `Esc` | モードを抜ける / メッセージを消す |

この表は `src/keys.rs` の `HELP` と同じものを載せている。ヘルプ画面もそこを読むので、
実装と説明がずれない。

## 読んでいるデータ形式

Acta が書き出す Markdown と JSON をそのまま読む。

```
posts/YYYY/MM/DD/YYYY-MM-DD.md     デイリーノート
projects/<dir>/project.json        プロジェクトとタスク
projects/<dir>/knowledge.md        プロジェクトのナレッジ
```

デイリーノートの中身は次の形。

```markdown
# 2026-02-26

<!-- acta:comment
id: d1d0d072-1dae-4a86-ae77-5b100373d3ad
created: 2026-02-26 11:25
created_ms: 1772072708000
tags: ToDo, Terraform
-->
# ToDo: 2026/02/26（木）
- プロジェクト名
  - [ ] 未着手
  - [-] 進行中
  - [x] 完了
<!-- /acta:comment -->
```

ToDo として扱うのは、`tags` に `ToDo` を含むエントリか、本文が `# ToDo` で
始まるエントリ。チェック欄の `[ ]` / `[-]` / `[x]` が Backlog / InProgress /
Done に対応する。プロジェクトは `archivedAtMs` が 0 より大きければアーカイブ済み。

nota 固有の状態は `.nota/` に置く。今のところ手で並べたプロジェクトの順だけで、
消しても既定の並びに戻るだけ。Acta はこのディレクトリを見ない。

## 開発

```sh
mise run test           # cargo test
mise run lint           # clippy + fmt --check
mise run fmt            # cargo fmt
```

実データに対する健全性チェックは `#[ignore]` にしてある。全ノートで原文を
復元できるか（書き戻しの安全性）を確かめるので、データ形式に手を入れたときは
これを通す。

```sh
NOTA_DATA_DIR=/path/to/Acta cargo test -- --ignored --nocapture
```

データディレクトリを解決できない環境では、このテストは理由を出して何もせず終わる。

### 構成

| ファイル | 役割 |
| --- | --- |
| `src/model.rs` | Acta のファイル形式。原文を保持したままパースする |
| `src/store.rs` | ディレクトリ走査と読み書き |
| `src/config.rs` | データディレクトリの解決 |
| `src/editor.rs` | `$EDITOR` の起動 |
| `src/app.rs` | 状態と更新（`App` と `Msg`） |
| `src/keys.rs` | キー入力から `Msg` への変換 |
| `src/ui.rs` | 描画。状態は変えない |
| `src/smoke.rs` | 描画と実データ読み込みの検証 |

状態は `App` に集約し、変更は必ず `Msg` を通す。描画は `App` を読むだけ。
キー入力の解釈は `Mode`（`Normal` / `Search` / `Confirm` / `Help`）で分ける。

エディタの起動だけは端末の制御を伴うので、`App` は「開いてほしい」という要求を
置くだけにして、実際の起動はイベントループが行う。`App` がプロセスや端末に
触らないので、編集の流れをテストから素通しで検証できる。

一覧の要素は添字ではなく名前や行番号で追う。保存すると `updatedAtMs` が変わって
並びが入れ替わるため、添字を持ち回ると別のものを指してしまう。
